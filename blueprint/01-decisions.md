## Routing and identity

| id | decision |
| --- | --- |
| B21 | Filesystem routes only. Suffixes: `*.page.tsx`, `*.layout.tsx`, `*.root-layout.tsx`, `*.segment.ts`. The id string inside `createPage("…")` is written and rewritten by codegen. The runtime matches the pattern from the generated record, not the string in the file. A mismatch between the file path and that string is a build error (S4). |
| B22 | Canonical path is computed once, at ingress, and every later stage receives that path. A backslash in the path is read as `/`, as WHATWG's URL parser reads it: Bun and Workers hand Flare the parsed URL with no backslash left (measured 2026-10-16: Bun 1.4.3 turns `/\admin` into `//admin` and `/a\b` into `/a/b`, workerd under Miniflare the same, Node's raw target is read the same way since BUGS.md 163), so a path is one answer on every runtime. Then `//`, absolute-form, and control characters are 400, never a redirect. Empty-segment, trailing-slash, and case folding (when `caseSensitive` is false) redirect: 301 for GET and HEAD, 308 for every other method (N3-31, the open-redirect class). Case folding is toward the matched route and in one redirect with the rest: a segment a static pattern segment consumed takes that segment's spelling, a locale param equal to a configured tag ignoring case takes the tag's spelling, and every other param value and percent-escape is left as sent. A path that matches no route is not folded. |
| B23 | There is one path-prefix function. It compares on segment boundaries after case folding. `startsWith` on a pathname is a lint error (`flare/path-prefix`). |
| B24 | Redirect targets are validated as raw strings before `new URL`. `new URL("//evil")` is not a validator. The only builder is `server/redirect/builder.ts`. `flare/location-only-in-redirect` rejects a hand-built `Location` header anywhere else. |
| B25 | Effective auth is computed from the loaded route modules, before any cache read (D1). Codegen `hint` is checked against that result at prerender time; a mismatch fails the build. The runtime never branches on `hint`. |
| B26 | Effective auth is `requires \|\| reads`. `authenticate` requires. `authenticateOptional` reads. An `authorize` without `authenticate` reads, because its answer is per caller (round-3 correction to D1). |
| B27 | A required-auth chain is never stored in a shared store. An optional-auth chain stores the anonymous render only (D15). |
| B28 | `callerData` is the leaf route's arguments. `callerChain` is the array of `{ route, args }` from the root down (D13). |
| B29 | Under a failed layout gate, descendant page loaders may still run. Their data is not serialized. A gate that must not run later work is `preloader` or `authorize`, which are sequential (D30). |
| B30 | A navigation whose matches, pages and layouts alike, are all fresh in the client cache sends no request (a Back or Forward step also paints held stale matches, then revalidates: B137); a mounted layout is not fresh by being mounted (`dx/cache.md` client `staleTime`, revised 2026-10-13 by BUGS.md B19). Otherwise layout loaders are never skipped by `_flare_stale`. Page loaders may be. Layout ids in the stale list are ignored. Unknown page ids are ignored. The value is the page match ids joined with one space. A match id is raw params plus raw search, and a parsed URL keeps no raw space in either. The param is capped at 8 KiB of UTF-8; above that the request is treated as all-page-loaders-stale (D6, N3-5). |
| B31 | Match ids are raw params plus raw search on both sides. The raw search is the decoded, unvalidated record (`+` a space, a malformed escape as written); the id holds it written back with keys sorted and values encoded, so every spelling of one value set is one id and one cache entry (BUGS.md 147). Params stay encoded (B81). `effects.loaderDeps` receives the raw search, typed as raw (D9). |
| B32 | Cache keys are `static:<build>:<routeId>:<rawParams>`. There is no identity class in the key (B73). There is no `cache.ssr.key` callback. An author-supplied key was the cross-user leak. A required chain is still never stored (B27). The policy class `anonymous` is not a key segment. |
| B33 | `cdn.vary` does not exist. Variants are different URLs (D3). |

## Server functions

| id | decision |
| --- | --- |
| B41 | Endpoint is `POST` or `GET` `<basePath>/_flare/fn/<id>`: under the router's `basePath` like every route, so a proxy that forwards only the base reaches it. With `basePath` `/` it is `/_flare/fn/<id>`. Id is `sha256(root-relative path + "\\0" + export name)` truncated to 16 hex chars. Duplicate names in different files are allowed. Two functions that hash equal fail the build (D19, without the form-baking half that D50 removed). `name` is not a config field. The export name is the binding (B85). |
| B42 | Order: parse URL, lookup (404), OPTIONS 204 with `Allow`, method mismatch 405 with `Allow`, CSRF, auth, input, handler, envelope, finalize (D29). |
| B43 | GET input is the param `_i=<wire value>`, the input in seroval's JSON form (B145), client-capped at 8,192 characters. Beside it the client sends `_b=<its build id>` when it has one; the server reads only the shape of `_b`, never its value. A cache keyed on the URL, the browser's or a CDN's, then keeps each build's answers apart, so after a deploy a client never reads an answer the previous build cached, whose `flare-build` would force a reload for the whole `max-age` (revised 2026-10-17, plan 21 8.5, BUGS.md 199: a revalidating retry misses a CDN that ignores a request's `Cache-Control`, and a build-keyed URL needs no retry). Any other param, or a second `_i` or `_b`, is 400. Repeated keys are not used on this endpoint. POST body cap is 1 MiB. A pass-through `Response` still receives `private, no-store` unless the registration is GET, has no auth, and sets `cache.maxAge` (D8, D27). |
| B44 | CSRF uses the origin the adapter resolved. `Sec-Fetch-Site: none` is accepted for GET only (D23). Fail-open when Origin, Sec-Fetch-Site, and Referer are all absent applies only to a function with no `authenticate` and no `authorize` (D27). `same-site` is accepted only for hosts on an explicit allow-list passed to `createServer`. A `.response()` route's request with any method but GET and HEAD gets the same check, as a POST, before its loaders run; the fail-open there applies only to a chain that neither reads nor requires auth (plan 21 4.3, BUGS.md 233). One `.response()` route may drop that check with `crossOrigin: true`, for a sender on another site whose request its handler proves (a signed webhook, an OIDC form_post, a SAML endpoint); it adds no CORS header. A route that answers only GET or OPTIONS, or whose chain, layouts included, has `.authenticate()`, `.authenticateOptional()`, or `.authorize()`, is refused by codegen and `createServer`, since a forged cross-site request would act as the visitor (revised 2026-10-17, BUGS.md 273). Such a route runs with no session, its server-function calls included: `authenticate` is never asked, a server function that needs a session throws a bug naming the route, and `serverCtx()` is what `serverContext` gives the request without its Cookie and Authorization (BUGS.md 282). |
| B45 | The client stub of a server function warns, in dev only, if it is invoked during a client render, and the call proceeds. It never throws: the render check is a heuristic (an owner and no observer), and a library that runs a callback synchronously inside a render, such as a suspense query's `queryFn`, matches it while being a correct call (revised 2026-10-13, BUGS.md B36, which a throw there caused). A production bundle has no check. The build tripwire scans every emitted chunk of both graphs. A client chunk, of the browser or a Web Worker, that contains a server chain method's function body, a `createServerOnlyFn` body, the `.server()` body of `createIsomorphicFn`, or a module path under `src/server`, `src/adapters`, or `src/vite`, fails the build. A server chunk, of the ssr environment or the Workers bundle, that contains a `createClientOnlyFn` body or the `.client()` body of `createIsomorphicFn` fails the build (B9). |

## Cache

| id | decision |
| --- | --- |
| B46 | Shared HTML is stored only when the document status is 2xx, the data response is ok, the body contains `<html>` and `</body>`, and the chain is allowed to be stored (B27). Redirects are not stored. `Location` from an upstream response is not stored. Security headers are not stored (N3-1 and the ISR class). |
| B47 | `storedAt` is the render start. When `revalidate` is set, TTL is `revalidate * 2`, capped at 24 hours, and `stale` begins at `revalidate`. A stored entry with no TTL is a blueprint violation. `isr: true` and `isr: {}` are on-demand and use a TTL of 24 hours. An omitted `revalidate` uses that same 24 hour TTL and is rendered at build only when `params` exist (B73). The 24 hour TTL is a real miss. Nothing background-refreshes before it. Tag or key purge still misses before the TTL. |
| B48 | Seeds carry `renderedAt`, `tags`, and `seed: true`. A seed without `seed: true` is refused. A purge `get` returns `{ data: { tombstone: true }, storedAt }`, not null. An ISR seed is served only when its `renderedAt` is greater than that `storedAt` (B86). Key purges write a per-key tombstone. Tag purges bump a tag epoch. `get` is two reads plus one per tag (N3-3, N3-16, N3-17, N3-19). |
| B49 | Prerender that receives a status outside 200–299, or throws, fails the build with the route id on stderr and a non-zero exit (N3-1). |
| B50 | The public origin baked into a stored page is `createServer({ site })`. The request `Host` is never written into a shared body. |
